# Modbus Dev 需求说明

日期：2026-10-22。状态：首版需求基线；阶段实施记录见 ../logs/implementation.md。

## 1. 定位与交付

独立的 Modbus 通信测试、模拟、数据回放与诊断软件，仓库为 `D:\zx-code\modbus_dev`。
核心能力同时用于无界面 CLI 和可选桌面 GUI。单次只运行一个会话，不设计多会话管理系统。
软件作为独立产品安装、运行和验证，仅依赖明确声明的第三方库。功能范围限定为通用 Modbus 通信、模拟、回放和诊断。

后台运行指普通 CLI 进程；不提供 Windows 服务、开机自启、远程控制 API。
初版未提供 TCP 主站；现追加单目标 TCP 主站，功能对齐现有 RTU 主站，
范围、默认权限、整轮预算及验收标准见 [TCP 主站需求与设计](tcp-master.md)。
任意寄存器编辑和更多功能码仍不在本轮范围。

## 2. 第一版功能

2026-10-23 追加确认：RTU 本轮扩展 FC03/04/06/16、主从站只读 / 读写权限、保持区写入与输入区波形分离。
新增实际收发数值 5Hz、趋势曲线 2Hz、最近十秒有界窗口；隐藏曲线停止绘制，通信不受 UI 刷新影响。
当前需求升级为最多八点、逐点操作/区域及 TCP 独立两区读写，详见 [独立测点与周期预算](point-configuration.md)。下表为初版基线；当前行为及验收边界以 [RTU 补充说明](rtu-register-monitor.md) 为准。

| 编号 | 能力 | 边界 |

| F02 | RTU 只读从站 | 响应 FC03/04；不接受写入；数据时钟独立于轮询频率 |

### 配置修改与界面语言

全部配置在会话启动、运行、重连和停止收尾期间禁止修改，停止收尾完成后可编辑。
通信参数由下一次启动读取并校验，无需重启软件；模式与数据源调整只更新相关字段和说明。
界面提供跟随系统、简体中文和英文；停止通信后切换语言立即刷新文案，偏好单独持久化，
不进入通信配置或改写已有运行结果。配置导出继续使用版本化 JSON，CLI 不依赖 Qt。

全部配置共用立即自动保存与启动恢复机制：仅在未运行状态下修改时保存，覆盖通信参数、
测点、日志设置、结果目录和语言。下次启动自动恢复配置但不自动通信；输入未完成的内容可作为草稿恢复。
写入失败在当次修改时明确提示并保留旧文件；不采用延迟保存、退出补存或退出自动重试。
配置读写由统一服务负责，各界面组件不自行实现文件保存，手动通信配置导入导出只支持当前格式，旧版本或无版本文件提示不兼容。

### 2026-10-23 测点与界面补充

同一设备最多八个测点配置区，各点可独立启用、设置零基起始寄存器地址、选择适用的常量/正弦/三角波并配置
独立参数；名称可选。至少启用一个点，禁用点不参与通信、地址冲突及线路预算。
数据类型、排列可逐点配置并混用；类型定义、宽度和编解码为各通信角色的公共能力。
整数支持常量/三角波，float32 支持常量/正弦/三角波；周期、站号和连接参数为公共设置，排列逐点明确保存。
不新增比例、偏移或工程值预览，输入直接按所选类型编码。详见[数值类型约束](numeric-types.md)。
界面分为“连接与时序 / 数据设置 / 其他设置”：所有时序在连接页，数据页只保留逐点操作、区域和测点参数，
日志保留移至其他设置。任务 JSON 只支持显式版本 4；其他版本不迁移，需重新配置。不扩展多设备、多会话或新数据源。

坏质量 DYN 点不伪装为当前好值：主站跳过相应点，从站撤下相应点的可读值。
实施顺序为 TCP 只读从站、RTU 只读从站、GUI；DYN/CSV 离线输入暂缓，不作为从站或 GUI 的交付前提。
不自动循环 DYN、拼接时间缺口或倍速回放；以后增加时必须定义其时间和质量语义。
严格回放遇到交易失败或落后完整周期时失败退出；持续发数记录异常、跳过失效槽位并按策略重连。

## 3. 性能和稳定性

- P01：100/200 ms 发数采用单调时钟和绝对槽位，不使用“交易完成后 sleep 一个周期”。
- P02：交易总预算包括准备、静默等待、写入和应答；不得以隐式重试突破槽位预算。
- P03：RTU 按波特率、校验位、停止位和所有交易计算线路预算；多组写入/读回不能套用单次交易预算。TCP 不套用串口线路公式。
- P04：收到迟到数据后保守重启帧间静默；连续噪声等待有上限；剩余预算不足则跳过，禁止追赶突发。
- P05：保留 Windows 写入路径不引入 50 ms flush 轮询的回归要求；不能把 write 返回当作物理发送完成。
- P06：RTU 无事务号，超时后的同地址 ACK 不能恢复成确定成功，除非有明确可靠的重新同步依据。
- P07：串口错误不得导致主循环退出失控；持续模式有节制重连，严格模式明确失败。
- P08：GUI 刷新不高于 5 Hz，日志批量追加并限制保留条数；通信路径不调用 UI、磁盘 flush 或阻塞日志消费者。
- P09：日志队列和 UI 缓冲均有界；溢出可见并计数，结果标注证据不完整。日志写入失败不能报告运行成功。
- P10：所有阻塞 I/O 有期限；停止不等待一个完整长回放，正常停止需关闭串口、socket、子进程和日志。

100 ms 是目标调度周期，不承诺操作系统或 USB 串口硬实时。验收必须报告实际发送间隔均值、P95/P99、
计划偏移分布、超时、跳槽和日志丢失，不能只看平均频率。默认调度容差为周期的 10%，可配置；
仅当相邻周期首笔实际写调用间隔超过“周期 + 容差”时计调度迟发，等于上限及首笔不计。
同周期分组和读回不重复判定；计划偏移保存在详细日志和会话汇总，不作为主要告警。
告警本身不停止任务，也不改变绝对调度和交易预算。应答超时独立配置。

## 4. 可观测性

应答有效性与请求关联确定性分别记录；历史关联风险不能反复计作新通信故障。
实际提交驱动的 TX 值与确认状态分开，确认不得制造曲线点、刷新数据时间或提升无效数据质量；严格模式的关联校验不因此放宽。

每条事件包含 UTC 时间、单调时间、会话 ID、事件代码、级别、阶段和结构化详情。
通信故障包含端口、设备地址、功能码、寄存器范围、超时预算、异常类型/码、重试状态和关联报文。
GUI 展示可理解的信息及处理建议；完整堆栈进入文件详情，敏感配置不直接记录。
相同告警 UI 可合并计数，但保留首次/末次时间；合并与原始证据丢失必须区分。
原始串口数据只称为驱动交付/提交证据，不称为物理线时间。

## 5. 兼容与独立交付

采用跨平台源码；Windows 发布包优先，麒麟 CLI 必须验证。GUI 不人为排除 Linux；Qt 依赖满足时可运行。
不同系统和 CPU 架构分别验证/打包。不承诺未验证的麒麟 GUI 环境。
不为 Python 3.7 维护兼容层，也不无故抬高最低版本；最低版本由选定依赖决定并记录。
CLI 安装不依赖 Qt。源码安装和独立桌面包共用业务代码，不强制使用 Cython。

提供统一 CLI 和可选桌面入口，共用配置模型和运行逻辑。安装包、运行配置和测试数据均有明确边界，验收可独立复现。

## 6. 完成标准

配置校验、调度、异常、停止、日志背压具有确定性测试；保留独立编码对端和固定报文样例。
Windows 虚拟 COM、Linux PTY、物理串口及标准 Modbus 设备验证分别记录，模拟测试不能替代物理串口验收。
100 ms 正常/迟到/超时/重连/持续噪声/日志压力场景均验证；GUI 开关前后对照调度统计。
独立安装后 CLI 可运行；可选 GUI 缺失不影响 CLI。
