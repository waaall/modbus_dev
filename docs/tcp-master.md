# TCP 主站需求与设计

## 范围

新增标准 Modbus TCP 主站，与现有 TCP 从站配套，亦可按相同协议访问外部设备。
CLI 与 GUI 使用同一会话入口；每个窗口/进程仍只有一个会话。本机联调分别启动主站和从站，
不增加单窗口双角色、多设备管理、扫描、并发流水线、线圈、RTU-over-TCP 或 TLS。

一个会话连接一个目标 IP、端口和 Unit ID。目标接受 IPv4/IPv6 字面地址，不执行可能无界阻塞的 DNS；
现有 TCP 从站仍仅监听 IPv4。端口范围 1～65535，默认沿用本机配套端口 1502；
Unit ID 沿用现有 1～247 范围，不提供 TCP 广播语义。

## 配置与行为

- `mode=tcp-master`；沿用 `schema_version=4`，新增字段为兼容的可选字段，不重置原有自动保存。
  现有版本 4 任务继续接受；新模式和新字段不保证能被旧发布包识别。
- `host`、`port` 在主站表示目标，在从站表示监听地址；串口字段不参与 TCP 校验或运行。
- `connect_timeout_ms` 独立限制一次 TCP 连接，默认 1000ms，范围 1～60000ms，仅 TCP 主站使用。
- 新建 TCP 主站默认 `access_mode=read-only`、测点操作为 FC04；必须显式选择读写权限才能执行写入。
  不修改既有 RTU 主站的默认权限或已保存的显式操作。只读配置含写入点时拒绝启动，不静默跳过。
- 最多八点，沿用类型、排列、逐点操作、地址冲突校验、常量/正弦/三角波及完整点分组规则。
  FC03/04 读取对端；FC06 仅支持 16 位点；FC16 支持现有全部类型；写后按逐点频率用 FC03 读回。
- 一个长连接上一次只进行一笔请求/应答，连接可跨周期复用。无库级隐式请求重试。

## 周期、失败与停止

周期范围仍为 50～60000ms，所有测点共用绝对槽位。`timeout_ms` 为相对计划槽位的整轮交易预算，
须满足 `0 < timeout_ms < period_ms`；所有请求及读回共用同一个截止时刻，不因分片、错误事务号或下一笔请求延期。
不使用 RTU 波特率、字符时间、静默间隔或线路最低周期公式；网络/对端耗时未知，界面不虚构可保证的周期预算。
连接超时与交易预算分开；重连耗时不顺延原计划槽位，也不回放过期周期。

持续模式连接失败、连接丢失或无有效应答后，关闭旧连接，至少等待 1 秒才再次尝试连接；
协议异常响应可保留连接并在下一周期继续。严格模式连接失败、交易失败或读回不一致立即失败停止。
不重发失败交易；持续模式下一有效周期是一次新的操作，不代表上次操作已经撤销或执行失败。

写入字节已提交 socket 但没有有效确认时，记录“写入结果未知”，不能推断设备未执行或自动补发。
事务号只解决应答关联，不证明设备业务已完成，也不消除失联写入的不确定性。
TCP 不沿用 RTU 会话级粘滞 ACK 关联不确定标记；每笔未知写入独立记录。
TX 数值仅在完整请求交给 socket 后发布，ACK 确认与读回一致分别记录；分片发送不提前发布完整 TX。

连接、收发等待以至多 10ms 的短轮询检查停止和日志健康状态，共用固定截止时刻。
停止后释放 socket，再沿用现有日志和结果收尾流程；不承诺操作系统调度下的硬实时。

## 模块边界

- `domain` 继续维护配置、数值、点表、请求规划及无库依赖的 Request/Reply。
- `application.session` 共用主站调度、策略、采样、读回比较、监视和记录；
  连接状态、周期准备、交易最小时间和请求间隔通过轻量引擎契约取得，不依赖 `.port`。
- RTU 引擎保留串口、静默、CRC 和粘滞关联语义；TCP 主站引擎独立负责主动连接、
  部分发送、固定截止接收、MBAP 验证和事务号匹配。
- 请求 PDU 构造复用 PyModbus 并放在引擎内部的小模块；TCP 帧编码继续复用固定版本 FramerSocket。
  不强行共用从站的监听器、多客户端循环、寄存器区或源更新逻辑。
- 接收先检查 MBAP 协议号和长度（长度 2～254），再按长度取完整帧；不扫描噪声寻找嵌入帧。
  校验事务号、Unit ID、功能码及响应长度/数量/写入回显；其他事务号独立记日志并在原期限内等待。
  缓冲和单次交付有界，超时/残帧/错误同事务响应后关闭连接，避免旧字节污染后续请求。
  整轮开始前预留足够事务号，容量不足时先关闭连接，由应用层统一重新建立和统计，
  避免同一连接中的事务号回绕误关联，也不在交易内部隐式连接。
- GUI 仅按角色调整连接文案、字段适用性和主站计数，复用现有测点、工作进程和有界监视链路。

选用当前 PyModbus 编解码而非直接使用同步客户端：当前固定版本同步事务入口具有自动连接路径，
接收接口使用自身超时而非本项目外部整轮 deadline，不能直接表达短轮询取消和完整发送时刻。
该判断仅针对当前锁定版本，不增加另一套通用协议栈。

## 验证与验收

1. 配置：新建默认只读、显式写权限、四功能码、类型/排列、地址冲突、无关串口草稿、周期与连接超时校验。
2. 独立字节对端：固定 MBAP/PDU、四功能码、异常响应、分片/粘连、错误事务号/站号/功能码、
   非法长度、残帧、迟到应答、部分发送、断线、整轮固定预算和事务号回绕。
3. 两进程：现有 TCP 从站配合 CLI 主站及 GUI worker，覆盖读取、写入读回、独立两区与混合数值。
4. 故障策略：拒绝连接、超时、断线重连、失败不补发、严格停止、合作停止和资源释放。
5. GUI：角色切换、只读权限、字段文案、监视与曲线、保存恢复及中英文；完整既有回归不退化。

自家主从互通不替代独立对端；本机结果不代表 Windows、麒麟、真实设备或发布包已验收。
具体运行结果保存在 `results/`，代表性总结与实施记录保存在 `logs/`。
